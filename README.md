# Heap File Management in C

A university project for the **Database Systems Implementation** course (2024–2025), exploring how database records are stored and accessed in fixed-size disk blocks. The project implements a **heap-file record layer** on top of a supplied **BF (Block File)** library.

Unlike a sorted or indexed file, a heap file stores records without maintaining a search index. The implementation uses file-level and block-level metadata to manage record placement and retrieval.

## Project scope

The implementation in `src/hp_file.c` provides the following heap-file operations:

| Function | Purpose |
| --- | --- |
| `HP_CreateFile` | Creates a block-based heap file and initializes its metadata in the first block. |
| `HP_OpenFile` | Opens an existing file and accesses its heap-file metadata. |
| `HP_CloseFile` | Closes the heap file through the BF layer. |
| `HP_InsertEntry` | Inserts a record into the current data block or allocates a new block when needed. |
| `HP_GetAllEntries` | Scans data blocks and prints records whose `id` matches the requested value. |

Each `Record` contains an integer `id` and fixed-length `name`, `surname`, and `city` fields. The heap-file header (`HP_info`) tracks information such as the last block ID, the number of blocks, and record capacity per block. A separate `HP_block_info` structure tracks the number of records in each data block.

## Storage design

- **Block 0:** file-level heap metadata.
- **Subsequent blocks:** packed records with block metadata.
- **Insertion:** append to the last data block when space remains; otherwise allocate a new block.
- **Lookup:** sequentially examine stored records and compare their IDs with the search key.
- **BF library:** supplies block allocation, reads, dirty-block marking, and pin/unpin operations.

This is a low-level storage exercise rather than a SQL database or a full DBMS.

## Build and run

The supplied Makefile targets Linux and GCC and links against the included BF shared library.

```bash
mkdir -p build
make hp
./build/hp_main
```

The heap-file example initializes the BF layer, creates `data.db`, inserts 1,000 generated records, searches for an ID, and closes the file.

To compile and run the BF-library example instead:

```bash
make bf
./build/bf_main
```

**Note:** `data.db` is generated by the example program. Remove an existing `data.db` before running the heap-file example again, since the program creates a new file rather than resetting an existing one. The supplied `make clean` target removes `data.db`.

The bundled `libbf.so` is a precompiled Linux shared library, so compatibility depends on the local platform and runtime environment.

## Concepts demonstrated

- Heap-file organization and sequential record scanning
- Block-based disk storage and metadata layout
- Fixed-size C records and binary data handling
- Buffer-management APIs (`BF_GetBlock`, `BF_AllocateBlock`, `BF_Block_SetDirty`, `BF_UnpinBlock`)
- Separate interfaces, implementation files, and example programs
- Compiling and linking C code against a shared library

## Academic context

Developed as assignment for the university course *Database Systems Implementation*. The goal was to implement a record-management layer over the provided BF block manager, as preparation for studying indexed storage structures in later assignments.

This repository preserves the original project implementation and its course-provided dependencies.
